# Audit 2026-09-13 — the duplicated comments, and what they are duplicates of

Every comment line of 25+ characters standing byte-identical in two or more files
of the SAME platform, across `App/`, `Shared/`, `android/src/main`, `Watch/`, `Widgets/`, `WatchWidgets/`.
Same-platform pairs are § 1–6; cross-platform pairs are § 7, and they answer a different question.
The file goes when the last cluster below ships.

86 groups over 56 files — but a comment block split across three lines counts three times,
and a house idiom counts once per site, so the raw number says nothing about how much work there is.
Collapsed by the code underneath, the 86 are **six clusters and about fourteen legitimate hits**.
Six missing components, not eighty-six problems.

## Why the comments are the tell

A copied comment is not itself the defect; it is the only cheap evidence of one.
`// why:` lines are written for the code beneath them, so the same sentence over two files
means the reasoning was carried across with the code — and in every cluster below
the code under the matching comments is near-verbatim too.
It is the same signal `scripts/card-parity.py` was built on, stated in its own docstring:
"the canonical form was near-identical code in a sibling file nobody had to look at."

## The fourteen that are not defects

Three kinds, and a gate has to know all three or it will cry wolf:

- **House idioms.** `// why: internal, not private — …` is a documented convention
  (`NumbersRunView.swift` states it), as is `split out purely for file size`
  and the `UI-test hook:` banner. These recur by design and must be normalized away, never baselined.
- **A rule pointer restated where it binds.** `Exposure surfaces render the TARGET side first
  (kern/docs/reports.md)` stands over four different implementations on two platforms.
  This is the CORRECT form — it cites the owning doc rather than restating the rule — so
  a comment carrying a doc path is evidence of good practice, not of a copy.
- **Forced duplication.** The widget and watch targets do not link Kotlin, so their copies are
  sanctioned by `docs/portability.md`; same-file overload pairs (`KernBridge.fastUnlocked`)
  and a property beside its DTO field (`hasPackedWords`) are not two implementations at all.

## 7. Across the platforms: 20 groups, and a different question

A comment standing in both an iOS and an Android file is not the same finding as one standing
twice on one phone. Here the duplicated sentence is not evidence of a copied component —
the two phones are supposed to render one rule twice — it is evidence of **a rule
neither phone should be minting**, which `CLAUDE.md`'s layer line already forbids.
Read that way, 20 groups sort into three piles.

**Platform's by the layer rule, and correctly so.** The pack-in/pack-out color rulings
(4 groups across `BoxCardRow`/`BoxView`/`BoxRows.kt`/`BoxSections.kt`) and the Pronouncer's
one-word-at-a-time stop are layout and audio, explicitly the platforms'.
`Exposure surfaces render the TARGET side first (kern/docs/reports.md)` is the model form:
four sites, two platforms, and every one of them cites the owning doc instead of restating it.

**Already kern's, restated rather than pointed at.** `dayPart(now, tz, target)` and
`rekeyingPrefixedVerbs()` are kern calls under comments that re-explain kern's reasoning;
the fix is a pointer, not a move.

**Minted twice — one find, not the eight first written here.** Reading each pair's CODE rather
than its comment cut the list to one: **the report-issue gate**. "A word the learner wrote
itself grows no report" stands five times, all platform-side, while `BoxEngine.reportIssue`
refuses only a card the profile has not joined — and an own word IS joined, so a report that
slips the five UI gates stores and exports.

The seven that fell away are the lesson. Four are the platforms' by the layer rule: the
audio-settings hint and the empty-search affordance both branch on a kern predicate and then
choose a STRING, the coach flag has no kern notion to belong to (`rg -i coach kern/src` is
empty, and moving it would mint a state machine to serve a caption), and the "report payload"
comment sits over two different views while what a report CARRIES is already `Feedback`'s.
Two more only restate a kern decision their own code already reads — a pointer, not a move.

And two were this audit's own error: `if let onTalk` is not a second predicate against
`hasBriefing`, it is the design component's injection seam FED by it (`SessionView.swift:73`),
and `setLearnerName`/`renameLearner` differ in spelling, not behavior. Matching comments were
read as matching defects without opening the code beneath — the one thing this file's own
opening section says not to do.

**What the comments could not see.** The real divergence in that cluster carries DIFFERENT
comments on the two sides, so no amount of comment matching would have found it: the reported-
catalog-cards list is newest-first on iOS and oldest-first on Android, each with a doc line
asserting its own, while kern's export is oldest-first. iOS reads its Box section in the
opposite order from the text it exports. A duplicated comment is a cheap tell, never a complete
one.

**Shipped from this section:** the blank-answer decision. `ONE primary action: an empty
field reveals, a typed one checks` stood over four sites on two platforms, with three
spellings of the predicate and iOS's disagreeing with kern on a newline.
`AnswerNormalizer.isBlankAnswer` took the predicate first, leaving the branch platform-side
on the reasoning that kern's submit was inert on blank — which was the bug, not the reason:
the Enter path never branched, so Enter on an empty field did nothing where the button on
the same field revealed. The branch is kern's now too; a blank submit MEANS reveal.

## What this means for the gate

The blocker recorded in `docs/backlog.md` — "90 comment texts, baseline them first" — was wrong
about the shape of the problem. There is no 90-entry baseline to keep.
A duplicate-comment check needs three exemptions (a comment matching a known idiom,
a comment citing a doc path, a file in a non-Kotlin-linking target) and then it is
near-green already: what remains is the six clusters, and those are work, not waivers.

So the order is cleanup first, gate second, and the gate lands nearly empty.
Its other half is the one `card-parity.py` still lacks and `LayerBoundaryTest` already solves:
derive the scanned set from the tree instead of hand-listing it,
since the file that cloned the choice grid was never on any list.
